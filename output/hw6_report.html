Play by play: which layer stops which attack?

✓ = the right decision with that layer alone. The visible-text attacks (x1, x3) are why one layer isn’t enough.

Code rebuilds the page as a person sees it, dropping hidden, tiny, white or off-page text, comments and links. The only layer that restores the true values. Blind to attacks written in plain sight.
Design gives the model no tools and asks only for five facts; Python applies the handbook rules and decides. Catches visible conflicts and vendor swaps. Can’t repair a fooled extraction.
Prompt tells the model to treat documents as data only. Strong but unenforced: alone it wrongly refused a clean email (p10) that said “ignore the earlier quote”.

Recommendation

Yes, put it on vendor mail, with guardrails

Use it as a fast first reader that prepares recommendations. Don’t let it send email or move money on its own.

Engage · humans decide

Why yes

  • It’s accurate. With all defenses it got 12 of 12 practice documents right, up from 8 of 12. All 10 exam answers match my reading of the handbook.
  • It’s safe where it counts. Across every test run: 0 trap calls. It never sent an email or approved a payment, and the defended model has no such tools.
  • It’s cheap. About $0.0002 per document.

Conditions

  • The agent never pays or emails; people do. Start by approving every payment for the first month, then move low-risk ones to a daily batch (see the options below).
  • Fix the two known holes first: text hidden by CSS classes in <style> blocks, and PDF text covered by a white box. Both slipped past the code layer in red-team tests.
  • Spot-check a sample each week and keep the audit log. A “do not recommend” caused by conflicting numbers goes to a person.
  • Expect some false refusals: the safe failure is “ask a human”, not “buy”.

The monthly bill

per month, all defenses on, handbook cache warm
How these were calculated

Per-document costs are measured. Defended, warm cache: the average of the 10 exam runs. Defended, cold cache: one request at cache-write prices, from the measured no-cache run. Undefended: the measured with-cache and no-cache runs (two requests per document). Monthly = cost per document × documents per day × 30. Assumes document sizes like the test set and, for warm figures, steady traffic.

Option 2 · how it runs

The daily batch, step by step

What the manager does each day

  • Open one list of the day’s clean, low-value recommended orders (vendor, item, price, lead time, minimum order, one-line reason).
  • Scan it, un-tick anything that looks off, and approve the rest in one click.
  • Handle the one-offs (anything not on the list) one at a time.

An order joins the batch only if all of these are true

  • The code, not the model, says all four handbook checks pass (approved vendor, price, lead time, minimum order).
  • The defenses removed no hidden or instruction-like text from the document.
  • The document has no conflicting numbers.
  • The order total is under the batch limit (proposed: $1,600; orders of $1,600 or above are always approved individually) and under a daily cap.

Always approved individually

  • New or pending vendors, anything over the limit, and any document the defenses flagged.

Before switching it on

  • Run month one with every order approved by hand. Track how often you agree with the agent, and switch on batching only when that agreement rate is one the owner is comfortable with.
  • Keep a stop switch: any wrong batched order sends everything back to approving one at a time.

At 1,000 documents a day the defended agent costs about a month with a warm cache and at most about if the cache never helps. The defenses don’t raise the bill; the design layer lowers it by needing one model request per document instead of two.
